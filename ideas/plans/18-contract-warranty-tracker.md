# 18. 계약서·보증서 자동 정리 & 만료 알림

## 최종 목표
- **집안의 계약·보증 문서 100% 디지털화, 만료·갱신·해지 기한 놓침 0건**
- 연 10만 원 이상 절약: 보증기간 안 무상 수리, 자동갱신 전 해지·재협상, 약정 만료 후 요금 재조정
- 새 문서 등록은 **사진 한 장 또는 PDF를 폴더에 넣는 것으로 끝** (추출·알림 등록은 자동)
- 문서 검색: "냉장고 보증서" 같은 말로 원본을 3초 안에 찾기

## MVP 범위
- 문서 종류 5가지: 보험, 임대차(전·월세), 통신 약정, 가전·전자제품 보증서, 정기 결제 서비스 약관
- 폴더 감시 → AI 추출 → 사람 확인 → 캘린더 알림 등록 → 월간 "만료 예정" 요약

## 데이터 구조 (문서 1건)
문서 종류, 상대방(회사), 계약 시작일, 종료일, 자동갱신 여부, 해지 통지 기한, 월·연 금액, 위약금 조건, 보증기간, 제품명·시리얼, 원본 파일 경로, 추출 신뢰도

## 기술 구조
- 입력: 로컬 폴더 또는 개인 클라우드 폴더 (사진·PDF)
- 추출: 비전 기능이 있는 LLM으로 이미지·PDF에서 바로 구조화 JSON 추출 → 날짜·금액 형식 검증
- 저장: SQLite + 원본 파일 (주민등록번호·계좌번호는 저장 전에 마스킹)
- 알림: 캘린더 이벤트(ICS 파일 구독 또는 캘린더 API) + 텔레그램 월간 요약
- 실행: **개인 PC 또는 비공개 저장소에서만** (공개 레포·외부 서버에 원본 금지)

## 알림 규칙 (기본값)
| 문서 | 알림 |
|---|---|
| 임대차 | 만료 6개월 전 "갱신 협의 시작" + **만료 2개월 전 "계약갱신요구 마감 임박"** (주택임대차보호법상 임차인의 갱신 요구 기간은 만료 6개월 전 ~ 2개월 전) |
| 보험 | 갱신일 D-30 (보험료 변동 확인·타사 비교), 자동이체 금액 변경 감지 |
| 통신 약정 | 약정 만료 D-30 (재약정·요금제 변경으로 할인 유지) |
| 보증서 | 보증 만료 D-30 "고장·이상 증상 미리 점검" |
| 자동갱신 서비스 | 해지 통지 기한 D-14 |

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 문서 모으기 | 집 안 문서를 사진으로 스캔 (한 페이지씩, 밝게, 전체가 보이게), 이메일로 받은 전자 계약서 PDF 모으기 | 문서 20건 이상 한 폴더에 |
| 1. 스키마·검증 규칙 | 위 데이터 구조 확정, 문서 종류별 필수 필드 정의 | 필수 필드 누락 시 "확인 필요"로 분류되는 규칙 |
| 2. 추출 파이프라인 | 이미지·PDF → 구조화 JSON, 신뢰도 낮은 필드는 사람 확인 대기 | 샘플 20건에서 날짜 필드 정확도 95% 이상 |
| 3. 확인 화면 | 추출 결과와 원본 이미지를 나란히 보고 수정·승인하는 간단한 로컬 웹 화면 | 1건 확인에 30초 이내 |
| 4. 알림 등록 | 승인된 문서의 기한을 캘린더 이벤트로 자동 생성, 수정 시 일정도 갱신 | 위 알림 규칙대로 일정 생성 |
| 5. 월간 요약 | "이번 달·다음 달 만료 예정" + 할 일(해지·재약정·점검) 목록 발송 | 매달 1일 자동 발송 |
| 6. 검색 | 자연어로 문서 찾기 (제품명·회사명·종류) | "세탁기 보증서" 검색으로 원본 즉시 열기 |
| 7. 자동 수집 | 메일로 오는 전자 계약서·보증서 첨부를 라벨 기준으로 자동 수집 | 새 전자 계약서가 사람 손 없이 등록 |
| 8. 6번과 연결 | 카드 정기결제(6번)에는 있는데 계약 문서가 없는 항목 탐지 → "약관 확인 필요" 알림 | 숨은 자동갱신 결제 발견 |

## 법·정책 주의사항
- 계약 문서는 개인정보·금융정보 포함 → 로컬·비공개 보관, 민감 번호 마스킹, 데이터 폴더 `.gitignore`
- LLM API로 문서를 보낼 때는 해당 서비스의 데이터 보관·학습 정책 확인, 필요하면 민감 부분을 가리고 전송
- 법정 기한 알림은 참고용: 실제 권리 행사 전에는 계약서 원문·전문가 확인

## 리스크와 대응
- 손글씨·흐린 사진 추출 실패 → 신뢰도 표시 + 사람 확인 단계로 보완
- 날짜가 "계약일로부터 2년"처럼 상대적으로 적힌 경우 → 계산 근거를 함께 저장해 검수 가능하게
- 처음 문서 모으기가 가장 귀찮음 → 0단계는 한 번에 다 하지 말고 "기한이 가까운 문서" 위주로 시작
