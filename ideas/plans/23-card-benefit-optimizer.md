# 23. 카드 혜택 최적화 & 전월 실적 알림

## 최종 목표
- **연간 카드 혜택(할인 + 적립 환산)을 지금보다 15만 원 이상 늘리기 (연회비 차감 후 순이익 기준)**
- 전월 실적을 못 채워 혜택을 놓치는 달 **0회**
- 12번(연말정산)의 카드 소득공제까지 합친 **"혜택 + 절세" 총가치 기준**으로 최적화
- 매달 확인 시간 5분 이하

## MVP 범위
- 6번의 정규화된 카드 사용 데이터 재사용
- 후보 카드 5~10장의 혜택을 규칙으로 구조화 → 내 지난 6개월 소비로 카드별 연간 순혜택 계산
- 지금 보유 카드 기준 월중 실적 진행률 알림

## 기술 구조
- 소비 데이터: 6번 파이프라인의 정규화 테이블 (날짜, 가맹점, 업종, 금액, 결제수단, 할부)
- 카드 혜택 데이터: 카드사 홈페이지의 **상품설명서 PDF를 직접 넣는 방식** (비교 사이트 크롤링은 약관 문제로 사용하지 않음)
  - LLM으로 규칙 스키마 추출 → 사람이 검수
  - 스키마: 연회비, 전월 실적 구간, **실적 제외 항목**(세금·상품권·관리비 등), 혜택 규칙(업종·가맹점, 할인율·적립률, 건당 최소 금액, 월 한도, 횟수 제한)
- 시뮬레이터: Python 규칙 엔진, 월 단위로 실적 판정 → 혜택 계산 → 한도 적용
- 최적화: 후보 카드 중 1~3장 조합을 전수 계산 (후보 20장이어도 조합 수가 작아 충분히 빠름), 업종별로 어떤 카드를 쓸지 배분
- 12번 연동: 카드 소득공제 문턱(총급여 25%) 전후의 신용·체크카드 전략을 같은 엔진에서 함께 계산
- 알림: 텔레그램, 실행은 로컬 또는 비공개 저장소
- 비용: 0원

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 자료 모으기 | 보유 카드와 관심 카드의 상품설명서 PDF, 6번 데이터 최근 6개월 | 카드 5~10장 자료 + 소비 데이터 준비 |
| 1. 혜택 규칙 추출 | 상품설명서 → 규칙 스키마(JSON/YAML), 실적 제외 항목 포함, 사람 검수 | 카드별 규칙 파일 완성 |
| 2. 업종 매칭 | 6번 가맹점 분류를 카드사 혜택 업종(카페·대중교통·통신·온라인쇼핑 등)에 연결 | 상위 50개 가맹점 매칭 |
| 3. 시뮬레이터 검증 | 보유 카드로 지난 달을 시뮬레이션해서 실제 명세서의 할인·적립 금액과 비교 | 오차 10% 이내 |
| 4. 최적 조합 계산 | 1~3장 조합별 연간 순혜택(혜택 − 연회비) + 12번 공제 효과 합산 순위 | "현재 대비 +N원" 리포트 |
| 5. 월중 알림 | 매달 15일·25일 카드별 실적 진행률, "남은 N원은 A카드로", 혜택 한도 소진 시 "B카드로 전환" | 2개월 연속 실적 미달 0회 |
| 6. 변경 감지 | 카드사 부가서비스 변경 안내(보통 시행 전에 사전 고지)를 메일 라벨로 수집 → 규칙 갱신 알림 | 변경 공지 반영 누락 0건 |
| 7. 분기 재평가 | 소비 패턴이 바뀌면 조합을 다시 계산, 교체 시 순이득이 일정 금액 이상일 때만 추천 | 분기 리포트 자동 생성 |
| 8. 통합 리포트 | 6·12·17번과 합친 월간 재정 리포트에 "카드 혜택" 섹션 추가 | 한 번 입력으로 통합 리포트 |

## 법·정책 주의사항
- **본인용으로만**: 일반에 카드를 추천하고 발급을 연결해 수익을 내면 금융소비자보호법상 판매대리·중개 규제 대상이 될 수 있음
- 카드를 자주 새로 발급·해지하면 신용 관리에 영향이 있을 수 있고, 신규 발급 이벤트에는 조건(해지 시 반환 등)이 붙는 경우가 많음 → 교체 추천은 순이득 기준을 보수적으로
- 금융 데이터는 로컬·비공개 보관, 데이터 폴더 `.gitignore`

## 리스크와 대응
- 상품설명서 규칙 오해석 → 3단계 실제 명세서 대조로 검증, 오차 큰 카드는 수동 보정
- 가맹점 업종 분류가 카드사 기준과 다름 → 실제 할인 여부로 매칭 사전 학습
- 간편결제 경유 결제는 혜택 제외인 경우가 많음 → 결제 경로까지 규칙에 포함
