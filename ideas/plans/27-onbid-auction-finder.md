# 27. 온비드 공매 물건 알림 & 적정 입찰가 계산

## 최종 목표
- **관심 조건에 맞는 공매 물건을 놓치는 일 0건**
- 6개월 안에 첫 낙찰 1건 이상, 낙찰 물건의 **실현 이익(재판매 차익 또는 시중가 대비 절약액) > 부대비용 포함 총비용**
- 물건 1건 검토 시간 **5분 이하** (알림의 계산 결과 확인 → 입찰 여부 결정)
- 입찰은 본인이 온비드에서 직접 (자동 입찰 금지)

## MVP 범위
- 동산 위주: 차량, 전자기기·사무기기, 일반 물품 (부동산은 권리분석이 복잡해서 MVP 제외)
- 매일 신규 물건 수집 → 관심 조건 필터 → 예상 시세·부대비용·적정 입찰가 계산 → 알림

## 기술 구조
- 데이터: 공공데이터포털의 한국자산관리공사 온비드 공매물건 조회 API, 입찰 결과 조회 API (제공 필드·범위는 0단계에서 확인)
- 시세: 21번(물건 현금화) 엔진 재사용 — 쇼핑 API 신제품가 + 감가 규칙, 차량은 연식·주행거리 기반 시세 참고값 입력
- 부대비용 계산기: 입찰보증금, 수수료, 취득·이전 비용(차량), 운송·수리 예상비, 재판매 시 플랫폼 수수료
- 적정 입찰가: 같은 카테고리 과거 낙찰가율 분포 + 예상 시세 → "목표 이익률을 남기는 최대 입찰가"와 낙찰 가능성 함께 표시
- 유찰 예측: 회차가 넘어가면 최저입찰가가 내려가는 구조를 반영해 "지금 입찰 vs 다음 회차 대기" 비교
- 저장: SQLite (물건, 회차, 가격 이력, 입찰 결과, 내 입찰 기록)
- 알림: 텔레그램
- 비용: 0원

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. API 확보 | 공매물건·입찰결과 API 활용 신청, 응답 필드(감정가, 최저입찰가, 회차, 입찰기간, 물건 상태 설명) 확인, 온비드 이용약관 확인 | 샘플 물건 50건 저장 |
| 1. 수집기 | 매일 신규·변경 물건 수집, 회차별 가격 변화 추적 | 7일 연속 수집 성공 |
| 2. 낙찰 이력 백필 | 카테고리별 과거 입찰 결과 수집 → 낙찰가율 분포 | 카테고리별 낙찰가율 통계 |
| 3. 관심 조건 | 품목·지역·가격대·최소 예상 이익 조건을 설정 파일로 | 필터 결과가 의도와 일치 |
| 4. 시세·비용 계산 | 21번 시세 엔진 연결, 부대비용 계산기 | 물건별 "예상 순이익" 표시 |
| 5. 적정 입찰가 | 목표 이익률 기준 최대 입찰가 + 과거 분포 기반 낙찰 가능성, 유찰 시 다음 회차 비교 | 과거 데이터로 검증: 제안가로 입찰했다면 낙찰됐을 비율 확인 |
| 6. 알림 | 신규 매칭 물건, 유찰 후 가격 하락, 입찰 마감 D-1 | 2주 실사용 |
| 7. 소액 실전 | 소액 물품으로 첫 입찰, 물건 인수 과정·숨은 비용 기록 | 실제 비용을 계산기에 반영 |
| 8. 결과 추적·보정 | 내 입찰·낙찰·재판매 결과로 시세·비용 모델 보정, 21번으로 재판매 연결 | 6개월 목표 지표 확인 |

## 법·정책 주의사항
- 입찰은 본인 인증으로 직접: 자동 입찰·매크로 금지, 온비드 이용약관 준수
- 공매 물건은 대부분 **현재 상태 그대로 인도**: 하자·누락에 대한 반품이 어렵다는 전제로 보수적 계산
- 차량은 압류·저당 처리, 미납 세금·과태료 승계 여부, 이전 비용을 공고문에서 반드시 확인
- **반복적으로 사서 되팔면** 사업자 등록 대상이 될 수 있고, 특히 중고차를 반복 매매하면 자동차매매업 등록이 필요할 수 있음 → 개인 사용·간헐적 처분 범위를 넘으면 확인
- 입찰보증금은 낙찰 후 계약 포기 시 돌려받지 못할 수 있음

## 리스크와 대응
- 물건 상태 정보 부족 → 사진·설명이 부족한 물건은 이익률 기준을 높게, 현장 확인 가능 여부 표시
- 시세 추정 오차 → 처음엔 시세가 명확한 표준 제품(모델명이 있는 전자기기 등) 위주
- 숨은 비용 → 7단계 실전 기록으로 비용 항목 보완
