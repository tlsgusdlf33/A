# 26. 멀티 프로젝트 운영·손익 통합 대시보드

## 최종 목표
- **운영 중인 모든 프로젝트의 장애(크론 멈춤, 사이트 다운)를 15분 안에 감지**해서 사용자보다 먼저 알기
- 프로젝트별 **월 손익(수익 − 비용) 자동 산출**, 실제 정산 금액과 오차 5% 이내
- LLM API·호스팅 비용 급증을 **당일 감지**
- 전체 운영 점검 시간 **주 30분 이하** (주간 리포트 읽기 + 알림 대응)

## 핵심 설계: 모든 프로젝트가 따르는 "운영 연동 표준"
다른 Claude Code 세션에서 만드는 프로젝트들이 같은 방식으로 붙을 수 있게 표준을 먼저 정합니다.
- **하트비트**: 크론 작업이 성공할 때마다 `POST /hb/<프로젝트>/<작업>` 호출 → 예정 시간 안에 안 오면 알림
- **이벤트**: 오류·주요 지표(가입, 주문, API 호출 수)를 `POST /event`로 전송
- **헬스체크**: 웹 서비스는 `GET /health` 제공
- 각 프로젝트에 넣을 작은 클라이언트(Python·TypeScript 각 1개, 수십 줄)를 제공

## 기술 구조
- 프로젝트 목록: `projects.yaml` (이름, 레포, 배포처, 크론 일정, 헬스체크 URL, 수익원, 비용원)
- 수집 서버: Cloudflare Workers (하트비트·이벤트 수신, 크론으로 업타임 체크) + D1(SQLite) 저장
- 비용 수집 (공식 API, 읽기 전용 권한):
  - LLM API 사용량·비용 (제공사의 관리자 사용량 API)
  - 호스팅·저장소 사용량 (Cloudflare 등 분석 API)
  - CI 실행 결과 (GitHub Actions API)
- 수익 수집:
  - 애드센스 관리 API (보고서), 결제대행사(PG) 거래 조회 API, 디지털 상품 플랫폼 판매 API
  - 제휴·마켓플레이스처럼 API가 없거나 승인이 필요한 곳은 **월 1회 CSV 업로드**로 시작
- 대시보드: 정적 웹(Astro 등) + Cloudflare Access로 **본인만 접근**
- 알림: 텔레그램 (장애 즉시, 비용·매출 이상 당일, 주간 리포트 월요일 아침)
- 비용: 무료 티어 안에서 운영 가능한 규모

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 인벤토리 | 채택 프로젝트 중 배포된 것과 배포 예정인 것을 `projects.yaml`로 정리 | 프로젝트별 크론·수익원·비용원 목록 |
| 1. 연동 표준·클라이언트 | 하트비트·이벤트·헬스체크 규격 문서, Python·TS 클라이언트 | 샘플 프로젝트 1개에 5분 안에 연동 |
| 2. 수신·업타임 | Workers로 하트비트·이벤트 수신, 5분 간격 헬스체크, 누락 감지 | 일부러 크론을 멈췄을 때 15분 안에 알림 |
| 3. 비용 수집 | LLM API 사용량, 호스팅, CI 비용을 일별 수집, 프로젝트별 태그(API 키·프로젝트 분리)로 배분 | 프로젝트별 일 비용 표시 |
| 4. 수익 수집 | 애드센스·PG·판매 플랫폼 API 연동, 나머지는 CSV 업로드 화면 | 프로젝트별 월 매출 표시 |
| 5. 손익·대시보드 | 프로젝트별 월 손익, 추세, 상태 신호등(정상·주의·장애) | 실제 정산과 오차 5% 이내 |
| 6. 이상 탐지 | 규칙: 하트비트 누락, 오류율 급증, 일 비용이 7일 평균의 2배, 매출 급감 | 테스트 시나리오 4종 모두 알림 |
| 7. 주간 리포트 | 월요일 아침: 프로젝트별 손익·장애·조치 필요 항목, 20번(지원사업) 신청용 실적 내보내기 | 4주 연속 자동 발송 |
| 8. 각 계획에 연동 반영 | `ideas/plans/`의 다른 계획 문서에 "운영 연동" 단계 추가 권장, 새 프로젝트는 처음부터 표준 적용 | 운영 중인 모든 프로젝트 연동 |

## 법·정책 주의사항
- API 키는 비밀 저장소에, **읽기 전용 권한**만 사용
- 대시보드에는 매출·비용 같은 민감 정보가 있으므로 반드시 인증 뒤에 둠
- 수집하는 이벤트에 최종 사용자 개인정보를 넣지 않음 (집계 수치만)

## 리스크와 대응
- 수익원별 API 제공 범위·승인 조건이 다름 → CSV 업로드를 기본 경로로 두고 API는 점진적으로
- 모니터링 시스템 자체 장애 → 외부 무료 업타임 체크로 대시보드 자체를 감시
- 알림 피로 → 심각도 등급, 같은 장애는 묶어서 1번만
