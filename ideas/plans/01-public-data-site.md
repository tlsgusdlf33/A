# 01. 공공데이터 자동 갱신 정보 사이트

> 상태: 채택 (다른 레포에서 개발 중). 이 문서는 진행 중인 개발과 비교해 빠진 단계를 확인하는 체크리스트로 쓰세요.

## 최종 목표
- **12개월 안에 월 페이지뷰 3만 이상, 애드센스 월 수익 10만~30만 원**
- 데이터 수집부터 페이지 갱신까지 100% 자동, 사람 손은 **주 1시간 이하** (모니터링과 개선만)
- 검색 유입 비중 80% 이상 (광고비 없이 자연 유입으로 유지)

## MVP 범위
- 주제 1개, 데이터셋 1~2개, 지역 단위 페이지(예: 시군구 × 월)
- 페이지마다 "그 데이터를 보러 온 사람이 바로 얻는 답" 1개: 최근 값, 전월·전년 대비 변화, 간단한 차트
- 매일 자동 갱신, 사이트맵 자동 생성

## 기술 구조
- 수집: Python 스크립트 → 공공데이터포털(data.go.kr) Open API
- 실행: GitHub Actions 크론 (하루 1회), 실패 시 이메일·텔레그램 알림
- 저장: 레포 안 JSON/SQLite (작으면) 또는 Cloudflare R2 (커지면)
- 사이트: Astro 정적 생성 → Cloudflare Pages 배포
- 비용: 도메인 연 1만~2만 원, 나머지 무료 티어

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 주제 검증 | 네이버 데이터랩·구글 트렌드로 검색량 확인, 경쟁 사이트 3곳 분석 (그들이 못 주는 정보 찾기) | 월 검색량 충분한 키워드군 + 차별점 1줄 정리 |
| 1. 데이터 확보 | data.go.kr 활용 신청 (개발계정 → 운영계정 전환), 응답 형식·호출 한도·갱신 주기 확인 | 샘플 API 응답 저장, 이용허락 조건(출처 표시 등) 메모 |
| 2. 수집 파이프라인 | 수집 → 정제 → 저장 스크립트, 재시도·중복 제거·이상치 검사 | 로컬에서 30일치 백필 성공 |
| 3. 페이지 생성 | 지역×기간 템플릿, 차트, 요약 문장(데이터 기반 규칙 생성), 내부 링크(인접 지역·상위 지역) | 페이지 100개 이상 생성, 각 페이지에 고유 수치 존재 |
| 4. 배포 자동화 | Actions 크론 → 빌드 → Pages 배포, 실패 알림 | 7일 연속 무인 갱신 성공 |
| 5. 검색 등록 | 커스텀 도메인 연결, sitemap.xml·robots.txt, Google Search Console·네이버 서치어드바이저 등록, 구조화 데이터 | 색인된 페이지 수가 증가 추세 |
| 6. 애드센스 신청 | 개인정보처리방침·소개·문의 페이지, 메뉴 구조 정리 후 신청 | 승인, 광고 배치 (과도한 배치 금지) |
| 7. 개선 루프 | Search Console에서 노출 많고 클릭 적은 페이지의 제목·설명 개선, 월 1회 성과 점검 | 3개월 연속 PV 증가 |
| 8. 확장 | 같은 파이프라인에 두 번째 데이터셋·두 번째 주제 추가 | 사이트 2개 또는 섹션 2개 운영 |

## 필요한 계정·API
- 공공데이터포털 계정 + 활용 신청, GitHub, Cloudflare, 도메인 등록업체, Google Search Console, 네이버 서치어드바이저, Google AdSense

## 법·정책 주의사항
- 공공데이터별 이용허락 조건(공공누리 유형 등) 확인 후 출처 표시
- 데이터만 나열한 페이지는 "얇은 콘텐츠"로 평가될 수 있음 → 비교·추세·요약 같은 가공 가치를 반드시 추가
- 애드센스: 클릭 유도 문구, 광고와 콘텐츠 혼동 배치 금지

## 리스크와 대응
- API 장애·스펙 변경 → 실패 알림 + 마지막 정상 데이터 유지
- 색인 지연 (신규 도메인은 수개월 걸림) → 초기에는 페이지 수보다 품질 우선
- 경쟁 사이트 → 처음엔 좁은 지역·좁은 주제로 1위를 먼저 차지
