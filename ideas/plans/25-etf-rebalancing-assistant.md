# 25. ETF 자산배분 리밸런싱 알림 + 세후 계좌 배치

## 최종 목표
- **목표 비중에서 정한 허용 폭(예: ±5%p) 밖으로 벗어난 상태를 알림 후 3영업일 안에 해소**
- 같은 자산 구성에서 계좌 배치(일반·ISA·연금)를 바꿔 **연간 세금 부담을 줄이기**, 절감액을 리포트에 누적
- 리밸런싱 관련 작업 **월 5분 이하** (알림 확인 → 승인)
- 주문 오류 0건: 모든 주문은 승인 후 실행, 금액·가격 안전장치 적용

## MVP 범위
- 목표 비중 설정 파일 + 증권사 Open API로 잔고·시세 조회 (계좌 1개부터)
- 비중 이탈 감지 → 매수·매도 수량 계산 → 텔레그램 알림
- 주문 실행은 **모의투자 환경에서 먼저** 검증, 실계좌는 승인 버튼으로만

## 기술 구조
- 증권사 API: 한국투자증권 KIS Developers 등 REST Open API (잔고·시세·주문, 모의투자 지원)
  - 증권사·계좌 종류(ISA·연금저축·IRP)마다 API 주문 지원 여부가 다르므로 0단계에서 확인, 미지원 계좌는 "수동 주문 목록"으로 안내
- 엔진: Python
  - 리밸런싱 방식: 허용 폭 이탈 시(밴드) + 분기 점검(달력) 혼합
  - **현금흐름 리밸런싱 우선**: 새로 넣는 돈으로 부족한 자산을 먼저 사서 매도(세금·수수료)를 최소화
  - 세후 계좌 배치: 자산 종류별 과세 방식(국내 주식형 ETF·해외/채권형 ETF·배당)을 계좌별로 비교해 배치 제안
- **세법·한도 수치는 설정 파일로 분리**: ISA 비과세 한도, 연금계좌 위험자산 비중 한도(퇴직연금 70% 등), 금융소득종합과세 기준(연 2천만 원) 등은 매년 확인 후 갱신
- 안전장치: 지정가 주문, 1회·1일 최대 주문 금액, 시세 급변 시 주문 보류, 긴급 정지 명령
- 알림·승인: 텔레그램 인라인 버튼 (승인 / 수정 / 보류)
- 실행: 장 마감 후 계산, 다음 장 시작 후 승인된 주문 실행
- 저장: SQLite (목표 비중, 일별 잔고, 주문 내역, 세금 추정)
- 비용: 0원 (증권사 매매 수수료 별도)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. API·계좌 확인 | 증권사 Open API 신청, 계좌 종류별 조회·주문 지원 여부, 모의투자 키 발급, API 이용약관(자동 주문 관련 조항) 확인 | 계좌별 "API 주문 가능 / 수동" 표 |
| 1. 목표 설정 | 자산군별 목표 비중, 허용 폭, 자산군별 사용 ETF, 계좌별 제약을 설정 파일로 | 설정 파일 완성 |
| 2. 잔고·시세 수집 | 매일 장 마감 후 계좌별 잔고·평가액·현금 조회, 이력 저장 | 7일 연속 수집 성공 |
| 3. 리밸런싱 계산 | 이탈 감지 → 현금흐름 우선 → 필요한 경우만 매도, 최소 거래 단위·수수료 반영 | 과거 데이터 시뮬레이션에서 계산 오류 0건 |
| 4. 세후 배치 엔진 | 자산별 과세 방식 × 계좌별 세제 혜택 비교 → 배치 제안과 예상 절감액 | 현재 배치 대비 연간 세금 차이 리포트 |
| 5. 알림·승인 | 텔레그램으로 "무엇을 몇 주, 왜" + 승인 버튼, 승인 내역 기록 | 승인 → 주문 요청 흐름 동작 |
| 6. 모의투자 검증 | 모의투자 환경에서 4주간 전체 흐름 운영, 안전장치 테스트(한도 초과·급변·중복 주문) | 오류 0건 |
| 7. 실계좌 소액 적용 | 소액·단일 계좌로 시작, 체결 결과 대조 | 4주간 의도와 다른 주문 0건 |
| 8. 확장 | 여러 계좌 통합, 월간 리포트(비중 추이·세후 수익·절감액), 12번(연금 세액공제)·17번(대기 자금 금리) 연동 | 통합 월간 리포트 |

## 법·정책 주의사항
- **본인 계좌용으로만**: 다른 사람의 계좌를 대신 운용하거나 전략을 유료로 제공하면 투자일임·자문업 규제 대상
- 증권사 API 이용약관의 자동 주문·호출 한도 조항 준수, API 키는 비밀 저장소에 보관
- 투자 원금 손실 가능: 리밸런싱은 위험 관리 수단이며 수익을 보장하지 않음
- 세금 계산은 추정치: 실제 과세는 증권사 원천징수·국세청 기준

## 리스크와 대응
- API 장애·체결 실패 → 주문 결과를 반드시 재조회하고, 미체결은 다음 날 재제안 (자동 재시도로 중복 주문 금지)
- 잘못된 설정으로 큰 주문 → 1회·1일 금액 한도와 "평소보다 큰 주문" 추가 확인
- 세법 변경 → 매년 1월 설정 파일 검토 체크리스트
